## Context

保留 Python 抓取与 Node.js 批导入工具用于离线回填；正式应用和任务共享 TypeScript 数据契约与回源逻辑。现有 `movies`、`movie_localizations`、`movie_sync_jobs`、`sync_cursors` 作为兼容基础。

## Goals / Non-Goals

- **目标：** 管理员能验证选片和字段、看到任务真实进度；VidAll 服务端能安全获取缓存优先的电影详情；失败可恢复，重复执行不产生重复记录。
- **非目标：** 见提案中的范围排除项。此变更不承诺分钟级定时、译文完整覆盖或全年全量采集。

## Decisions

### 应用、存储与身份

- **Next.js App Router / TypeScript / Tailwind CSS / shadcn/ui**；Vercel Node.js Runtime。后台进度页低频轮询，仅在页面可见时刷新。
- **Neon PostgreSQL / `@neondatabase/serverless` / Drizzle ORM**。常规读取用 Drizzle；任务认领、去重、游标推进和 UPSERT 使用显式事务 SQL。保留一个现有项目与 `main` 分支；本地与 CI 用合成数据，Vercel 预览环境不持有生产写权限。
- **Auth.js + GitHub OAuth**。用稳定 GitHub 账户 ID 筛选受邀管理员，默认拒绝；所有后台页面与后台 API 在服务端校验会话与管理员资格。外部应用密钥不能访问后台。敏感操作保留不含秘密的审计记录。

### 1.3 管理员认证与审计

- Auth.js GitHub OAuth 使用 JWT Cookie，不存 OAuth access token、邮箱或昵称；Cookie 仅含认证所需的 GitHub 账户 ID、签发时间与 Auth.js 会话元数据，最长 8 小时（绝对时限）。邀请名单使用 `ADMIN_GITHUB_IDS`，逗号分隔正整数账户 ID，空值或任一条无效均拒绝所有账户。OAuth 仅请求 `read:user`，以 GitHub 用户接口返回的数字账户 ID 判定资格；每次读取后台页面、管理 API 或会话均重新核对。移除账户并使配置生效后，旧 Cookie 不再授权。
- 后台页面逐页在读取数据／处理动态段前调用服务端守卫，不依赖客户端、共享 layout 或代理作为唯一鉴权。未授权页面转至 `/login`；内部 `GET /api/admin/audit` 对无有效受邀会话统一返回 401，并禁止缓存（成功及错误均如此）。`/login` 和 Auth.js 流程端点不要求管理员会话；文档页使用原页面守卫，OpenAPI JSON 通过同一管理员会话检查。浏览器通过服务端 POST 操作发起、退出会话；登录后返回固定首页，退出后返回登录页，不接收外部跳转地址。`/login` 即使收到 Auth.js 的错误参数，也先用原服务端守卫复核已有会话和当前白名单：有效则返回固定首页，否则保留错误提示和重试入口。重复回调仍由 Auth.js 按 `state` 和 PKCE 拒绝；错误页不签发会话、不补写准入审计。
- 运行配置：`AUTH_URL` 为部署站点的规范 origin（生产 HTTPS；本地使用 `http://localhost:3000`，勿混用 127.0.0.1，以保持 OAuth 回调和 Cookie 同源），GitHub OAuth App 的回调 URL 为该 origin 加 `/api/auth/callback/github`；`AUTH_GITHUB_ID`、`AUTH_GITHUB_SECRET` 由 OAuth App 提供，`AUTH_SECRET` 使用强随机值（例如 `openssl rand -hex 32`）。本地配置放入忽略的 `.env.local`；生产配置与真实联调留到后续部署／验收。缺少或无效的 OAuth 配置时返回不可用状态，管理页面仍拒绝访问。
- 对有合法数字账户 ID 的 OAuth 回调，将准入判定 `admin.oauth.admission` 的允许／拒绝写入现有 `admin_audit_events`。写入失败不签发会话；只记录固定动作、GitHub 数字 ID 和结果，不写 OAuth 请求体、令牌、Cookie、原始错误或授权头。匿名请求及外部 Bearer 无可验证的 GitHub 身份，不写该审计表。审计页／内部接口展示最新至多 100 条真实事件，页面按类别、结果、时间和文本筛选及分页；数据库不可用时显示错误，不回退到演示数据。后续接入真实敏感写操作时各自写审计。
- 本地及 CI 使用合成身份、会话和 PGlite 验证默认拒绝、撤销后旧会话失效、OAuth 准入审计及写失败拒绝；检查生产构建的后台页面／管理 API 和两条文档路由对无 Cookie、仅持外部 Bearer 和已撤权会话均不返回受保护内容。不开启演示绕过。

### 1.2 数据层与兼容迁移

- 保留 `db/migrations/0001_initial.sql` 原样。按编号维护显式 SQL 迁移，Drizzle 只负责类型映射和查询，不使用 schema push 或第二套迁移历史。应用启动、构建和测试都不隐式连接或迁移 Neon。
- `0002_mvp_data_layer.sql` 只追加结构：为 `movies` 加可空的原片语言、片长；为管理后台新增审计记录，为同步新增任务模板及运行记录。旧元数据不回填、不伪造，旧导入器可继续写原列；任务模板与运行独立于旧的 `movie_sync_jobs`、`sync_cursors`。批次、游标推进、凭据存储细节和预算／回源租约随对应任务落地，不在本次迁移提前引入。
- 运行保存独立的配置快照及计划时间、开始时间、结束时间；`(template_id, scheduled_at)` 唯一，非定时运行没有计划时间。试抓允许在未保存模板时记录运行，正式运行必须关联模板。数据库约束保证重复调度的唯一键与 JSON 对象形态；配置校验、快照不可编辑、状态流转和事件派发由后续服务实现。审计存 GitHub ID、动作、目标、结果与时间，不存请求体或任意摘要；鉴权及写入审计在 1.3 接入。
- 运行时使用服务端专用、惰性初始化的 Neon HTTP Drizzle 客户端（`DATABASE_URL` 可用池化连接）；本轮只提供按电影 ID 与语言精确读取原始缓存行的内部查询，不触发回源、不应用 API 缓存策略、不改动静态页面。数据库 bigint 不转成 JS number；日期和时间以字符串读取，以保留 PostgreSQL 精度。

#### 迁移与回退

- 空库以 PostgreSQL 直连变量 `DATABASE_URL_UNPOOLED`，用 `psql "$DATABASE_URL_UNPOOLED" --single-transaction --set=ON_ERROR_STOP=1 --file=db/migrations/0001_initial.sql --file=db/migrations/0002_mvp_data_layer.sql` 初始化；已应用 0001 的环境只执行未应用的后续文件，不重跑 0001。将 `db/migrations/` 中尚未应用的迁移按文件名顺序逐一以 `--file` 加入同一事务，当前至 `0007_incremental_schedule.sql`。生产先在隔离分支演练，确认实际已执行版本和恢复点后再应用；不要根据环境名称猜测版本。迁移按版本显式执行一次，不忽略已存在的对象；失败整次回滚。应用回退时保留兼容的新增结构，不执行自动逆迁移。
- 本地和 CI 用内存 PGlite 验证空库路径及已有数据升级；合成记录覆盖电影、多语言、旧队列及游标，验证升级前后旧字段不变、旧导入可继续写且保持时间顺序和缓存期限，并验证新约束及 Drizzle 读写。生产执行留到 3.3，不创建云测试库。

### 2.1 管理员只读电影缓存

- 电影库和详情通过既有管理员守卫后直接查询 Neon 的 `movies` 与 `movie_localizations`。列表按电影 × 译文显示；URL 保留查询、语言、状态、排序、视图和页码。纯数字或 `#数字` 按 TMDB ID 精确匹配（保留 PostgreSQL bigint 精度），其他输入按原片名／当前行译文片名做忽略大小写的字面子串匹配。
- 状态由同一次请求时钟判定，优先级为已下架 → 超出保留期 → 已过期 → 新鲜；边界时刻计入前一层期限已结束。保留库中仍存在的旧记录便于管理员排查，不作删除或回源。每页最多 20 条，一次查询多看 1 条来判断是否还有下一页，并用稳定次序分页；顶部显示当页条数，不为每次检索扫描全库算总量。
- 详情没有指定语言时优先显示已保存的中文译文，否则选择英语；指定语言缺失时明确提示，不静默回退、不尝试抓取。显示实际存储的抓取、过期、保留、下架时间及可用字段，未知值留空或标明。未缓存的电影 ID 返回 404；数据库不可用和空结果分别展示，不回退到合成记录。
- 2.1 不加载远程海报，保留原有网格尺寸并显示占位和缓存中已有的路径；不引入第三方资源请求或假海报。详情中的 JSON 是本地缓存字段预览，不宣称对外接口已上线。首页示例影片不链接真实详情，保留进入真实电影库的入口。

### 任务配置与执行

- 表单分为选片条件、抓取内容、运行方式、同步模式。原声语言是筛选条件，译文语言是 TMDB 请求参数；请求 `zh-CN` 不保证上游不会回退到其他语言。首版字段组为电影基础详情与译文；演职员等扩展字段另立变更。
- 将任务配置和每次运行的配置快照分开。手动按钮立即创建运行记录并发送执行事件，不等定时扫描；实际开始可能因并发限制或限流而延后。试抓用同一套选片及抓取逻辑，最多 5 部；可以保存运行结果和诊断，但不写电影缓存或游标。
- 2.2 的试抓选片复用正式回填的 Discover 查询：按含首尾的上映日期范围和热度降序查询、排除成人内容，可按类别（任一匹配）和原片语言筛选；发现结果按 ID 去重，试抓最多查两页。试抓最多取 5 部并串行请求详情；普通的单条失败形成脱敏诊断，上游鉴权失败或 429 停止进一步请求。记录所请求的语言；只报告标题／简介缺失，不凭文本猜测实际翻译语言。试抓服务不持有数据库，后续编排只写运行结果，不写电影缓存或推进游标。
- 2.2 使用 `0003_sync_sample_runs.sql` 为运行增加仅用来保存脱敏摘要的结果列及最近运行索引。任务表单接入真实模板；配置校验后存唯一版本结构及定时选项，定时扫描不在 2.2 开启。保存模板和申请试抓与各自审计在同一 SQL 语句提交。试抓可直接使用未保存的表单内容，其运行快照与模板独立。
- 试抓从服务端立即发出 Inngest 事件，并以运行 UUID 作为事件去重键，事件体只含运行 ID。派发失败保留原运行并在页面区分；管理员可复用原 ID 重派，不创建重复样本。函数串行执行试抓，步骤分别读取快照／标记开始、抓取和保存摘要；终态运行的重复事件不再抓取。部署配置使用 `INNGEST_EVENT_KEY`、`INNGEST_SIGNING_KEY`、`TMDB_READ_TOKEN`，缺配置不发起试抓；正式写入走 2.3 的独立执行器。试抓记录与操作审计复用现有管理员会话与服务端守卫。
- **Inngest 编排，Vercel 执行。** Inngest 发送调度及任务事件并重试步骤；Next.js 的 Vercel 任务端点执行实际 TMDB 请求和 Neon 写入。端点验证 Inngest 签名，事件只带运行／批次标识，不带密钥和电影快照。不部署常驻 Worker 或 Redis。
- 一条固定调度每小时扫描到期计划。表单先支持每天／每周，默认 `Asia/Shanghai`；分别记录计划时间和实际开始时间。用 `(任务 ID, 计划时间)` 做定时触发的持久幂等键；为事件发送失败保留可重派发的运行记录，并让重试复用已有运行或批次。
- 回填固定本次选片；增量用 `/movie/changes` 分页，查询窗口不超过 14 天、保留重叠。先完整入队再推进对应任务的游标；任务扩大或改变选片范围时显式回填或重建游标。与片单无关的单次 404、429 和上游错误不触发下架。
- 任务进度持久化到 Neon，区分发现、入队、抓取、入库、失败，并记录重试和失败原因。按 `(tmdb_id, locale)` 去重，电影详情仅由更晚的 `fetched_at` 覆盖；不因重跑旧数据延长缓存寿命。
- 免费档优先：初始预算模型按 31 天每小时扫描一次、每天 500 条电影语言记录、另回填 5,000 条、每批 25 条且两步执行，约 3,948 次／月，不含发现、重试及其他用量。[Inngest 官方定价](https://www.inngest.com/pricing) 当前免费额 50,000 次／月、5 个并发步骤；应用先限制同时 2 个抓取批次，批大小按实际耗时调。上线首周核对 Inngest 实际用量与 Neon 计算用量，不以估算作为承诺。

### 2.3 立即同步与重试

- 已保存的「一次性回填」模板才显示并允许「立即同步」。使用数据库中的模板制作独立快照，冻结原选片与语言；每次最多 10 部、Discover 最多 2 页。增量、日／周定时尚不执行。使用同一签名入口和 TMDB Token；申请、重派、失败重试分别写审计。
- 应用 `0004_manual_sync_items.sql` 为每次正式运行建立冻结的 ID 清单及逐项进度。Inngest 正式事件仅带运行 ID。步骤分别读取配置、发现并固定片单，再逐部抓取和提交；只在步骤检查点暂存写库所需的规范化字段，不存原始响应或密钥。抓取后先标记「已抓取」，再在同一 SQL 事务中更新电影、译文及入库进度。事务失败仅自动重试当前写入，不再请求该电影。译文按更新时间单调递增（同时间或更早不写）；已下架电影不恢复；期限从原抓取时间起算 168／720 小时。未写入状态不会被当作入库成功。
- 429／凭据失效时停止剩余请求并记录未尝试项。派发失败用原运行 ID 重派；终态失败可在上游建议时间后创建一次关联重试，复用原快照且仅处理未完成项（首次发现未成功则重新发现）；不会重复处理已入库、已有同等／更新缓存或已下架的条目。正式任务不改旧队列和游标。跨任务共享冷却及计划扫描分别留到 3.2／3.1。

### Inngest 试抓

- 本地 Inngest 教学示例复用 `/api/inngest`：保持 Dev Server 在 `127.0.0.1:8288` 运行，另起 `CINERELAY_INNGEST_LOCAL=1 npm run dev -- --hostname 127.0.0.1 --port 3001` 供自动发现。仅开发模式明确启用时才注册 `validate-movie-selection`，且只连接本机 Dev Server；该模式不注册或派发正式试抓。生产模式仍要求签名，且不注册教学函数。
- `validate-movie-selection` 由 `cinerelay/dev.movie-selection.requested` 触发，事件携带 `selection`（上映日期范围、类别、原片语言、译文语言和单次上限）。持久化步骤 `validate-selection` 复用正式选片校验，只返回值是否有效和规范化后的范围（无效时仅返回固定错误码），不发起 TMDB 请求也不读写数据库。本地验收通过 MCP 核实已注册、指定运行完成及步骤输出。
- 启用试抓前先迁移数据库，在服务端设置 `INNGEST_EVENT_KEY`、`INNGEST_SIGNING_KEY` 和 `TMDB_READ_TOKEN`，并在相同的 Inngest 应用环境同步 CineRelay 的 `/api/inngest`。生产及本地测试都保持签名校验；CI 使用合成密钥、模拟事件接收及签名 HTTP 调用，不连接云服务。
- 在「任务配置」进入快速试抓，或编辑已保存的模板。正常派发后跳到运行详情；排队和执行时，在页面可见的前五分钟每 8 秒刷新。未确认接收的运行可手动重派。运行已记录但进程中断未更新派发状态的自动对账留到 3.1。运行和任务列表分别展示最新 50 条。
- 试抓结果只保留 ID、片名、字段存在标记、固定错误码和重试时间，不保留原始上游响应、简介或凭据。真实 TMDB 与真实 Inngest 环境的联调留到 2.5。

### 上游凭据与外部契约

- 管理后台支持 TMDB 凭据启停、轮换、最近错误和冷却状态。服务端加密，部署密钥和数据分开保存，不回显、不记日志。Web 与任务共享限额、并发预算和冷却状态；429 按 `Retry-After` 退避，未知配额范围按共享处理。
- VidAll 的可撤销 API Key 只放在其服务端，通过 Authorization 头调用；CineRelay 只存哈希。使用 Route Handlers + Zod + OpenAPI，Scalar 在 `/docs/api` 渲染同一份外部契约，不含管理端点、真实凭据或私有数据。
- 按电影 ID 和语言读缓存；缺失时限预算回源，并跨实例合并同键回源。过期且上游不可用时只在保留期内返回明确标记的旧值；无可用记录时返回可重试错误。沿用当前快照 7 天过期、30 天保留设计，生命周期维护由后续应用流程明确实现，不把过期视为下架。

### 2.4 对外详情契约

- `0005_consumer_api.sql` 增加外部密钥哈希、每 ID／语言的短期回源租约，以及 TMDB 共享闸门。管理员通过表单签发随机 256 位 Bearer 密钥，只在签发结果展示一次；列表只读非秘密标签、签发／撤销时间；只存 SHA-256 哈希，撤销与审计同事务提交，不影响 GitHub 管理员会话。
- 对外 API 默认 `zh-CN`，可选 `en-US`，不回退语言。ID 以正 PostgreSQL bigint 的十进制字符串传输；详情返回 `tmdbId`、`locale`、标题、公开电影字段和 `cache`（`hit`／`refreshed`／`stale`）及抓取／过期时间。无效参数 400、无效／撤销凭据 401、下架或上游 404 返回 404；其他不可用且无可用缓存时返回 503 与 `Retry-After`。错误只用固定错误码；所有 API 响应均 `private, no-store`，不会由共享缓存代答。
- 新鲜缓存短路。过期／缺失时按 (ID, locale) 取得 20 秒租约，竞争者重读后可返回尚在保留期内的旧值或带退避的 503，不发重复回源。主请求持租约再次读缓存才回源；写入时验证租约所有权、拒绝更新下架电影或覆盖较新译文。TMDB 读令牌暂用服务端环境变量；回源、试抓和回填每个上游 HTTP 请求共用数据库的单并发和每小时 600 次预算。429 持久化共享冷却，不切换凭据；3.2 延伸此闸门支持多凭据。
- Scalar `/docs/api` 同源请求 `/api/v1/openapi.json`；页面调用 `requireAdmin()`，JSON 逐请求调用 `getAdmin()`，未授权 JSON 返回 `401`。使用 `private, no-store`（页面由 Next.js 动态渲染提供），不把契约静态部署到公开目录。VidAll 可读仓库 `openspec/contracts/consumer-movie-api.openapi.json`；用 `npm run export:openapi` 从同一契约对象导出，生产构建 HTTP 回归核对两者相等。文档不含内部接口，不收集真实密钥，关闭网页交互请求。

### 3.1 调度、增量窗口与队列

- `0007_incremental_schedule.sql` 增加每次运行锁定的游标世代与独立待处理队列，不改旧导入器的数据契约。仅服务器设置 `CINERELAY_SYNC_SCHEDULER=1` 时注册每小时扫描。模板保存日／周和北京时间小时；管理员显式开启。范围、模式或计划变更时停用旧计划。同一模板和小时用原有唯一约束去重；每小时只生成当小时计划，不补建所有历史槽位；恢复派发每小时最多检查 100 条最近 24 小时的待派发记录，复用运行 ID 与事件 ID。
- 增量是对已有且符合范围的非下架电影进行刷新；新增电影走回填或首次回源。增量模板必须显式重建游标后才能运行，使用上一 UTC 日作为起点。按 UTC 截至昨日的闭合窗口查询 `/movie/changes`，首日与上次末日重叠；每窗口最多 14 天。最多检查 50 页，超量或分页失败时不推进窗口。
- 完整窗口去重、按缓存电影元数据过滤后，与游标推进在同一数据库事务写入按模板隔离的待处理队列。运行再领取最多 10 部形成冻结片单；积压由下一次手动／定时运行继续领取。范围修改后必须显式重建才能清理旧范围队列；过时快照不得修改新游标。在任务列表／编辑页显示是否已开启，运行详情保留每次计划时刻。

### 3.2 加密凭据池

- `0006_tmdb_credentials.sql` 存可启停的凭据及固定错误码、检查时间。设置服务端 `TMDB_KEY_ENCRYPTION_KEY`（标准 base64 编码的 32 随机字节）后启用池模式，使用 AES-256-GCM（每条独立随机 nonce，凭据 ID 作 AAD）。不回显、不写审计或 Inngest 事件；轮换通过新增和停用旧条目。引导阶段未设置加密密钥时仍可用 `TMDB_READ_TOKEN`；已设置池密钥但池无可用凭据时失败关闭，不自动绕回环境令牌。
- 每次取得共享预算才选一把启用且未被拒绝的凭据，优先最早可用条目；401／403 只标记该条，后续独立请求可选另一把，当前 HTTP 请求不重试。429 保留原凭据并写全局冷却；所有凭据与消费者共用同一小时预算和并发槽。重新启用前应先核对上游凭据，密文解密失败同样隔离，不返回原始错误。

### 部署

1. 将 Web、外部 API 与 Inngest 任务端点部署在同一 Vercel 应用，运行区域优先 `sin1`，靠近现有 Neon 新加坡实例。
2. 生产秘密使用 Vercel 环境变量／秘密配置；采用最小数据库权限。迁移在部署前显式执行，不在每次构建或预览部署自动写生产库。
3. EdgeOne 对外使用 `https://cine-relay.vidall.top`，HTTPS 回源使用 Vercel Production 固定域名 `cine-relay.vercel.app`（非单次部署域名）。生产 `AUTH_URL` 与独立 GitHub OAuth App 的回调 origin 均为公开域名；回调路径为 `/api/auth/callback/github`。初始接入对该域名全路径不启用 EdgeOne 缓存，静态缓存另行验收；透传 Cookie、授权及 Inngest 签名头。切换 DNS 前验证 TLS／回源 Host 与 SNI、公开域名下的 Next.js Server Action、回调、鉴权和匿名拒绝；生产实测回源 `x-forwarded-host` 为 `cine-relay.vercel.app`，浏览器 Origin 为 `https://cine-relay.vidall.top`；Next.js `serverActions.allowedOrigins` 只增加精确主机 `cine-relay.vidall.top`，不使用通配符，不关闭 CSRF 或 OAuth 检查。EdgeOne 不加速 Vercel 到 TMDB 的回源；国内加速范围遵守已有站点地域与备案要求。
4. 本地验收 → 显式迁移 → 受限生产烟测 → 开启定时和多凭据 → EdgeOne 接入验证。异常时可关闭定时／暂停抓取；回滚应用版本，不自动逆转已提交数据。

- `staging` 是日常 PR 的默认目标和固定 Preview 验收分支。功能分支可以独立开发；合入 `staging` 后由 Vercel Git 集成自动构建 Preview 并使用固定分支域名验证。`main` 仍是 Vercel Production 跟踪分支，不为预览推送到 `main`，正式发布须另行明确授权。
- 固定验收 origin 为 `https://cine-relay-git-staging-yaoshinings-projects-5cf8b607.vercel.app`。`staging` 的 `AUTH_URL` 使用该 origin；独立 GitHub OAuth App 的回调为该 origin 加 `/api/auth/callback/github`，不使用每次构建生成的地址。OAuth 和其他联调配置只用于 `staging` 的 Preview，数据库使用已迁移的 Neon 独立结构分支（不复制生产行）；登录验收阶段 Vercel 使用可查询及插入审计的非所有者角色。启用测试凭据池时，仅为该角色追加凭据插入、启停与健康字段更新，以及共享请求闸门必要字段更新的权限；生成仅限 `staging` 的独立加密密钥。试抓联调阶段仅追加 `sync_job_runs` 的创建和试抓生命周期字段更新权限，复用现有审计权限；不授权电影写入、计划、模板或外部密钥变更。测试事件必须发送至非生产 Inngest 环境。保留 Vercel 部署保护和 Inngest 签名校验。经确认允许 CineRelay 项目级 Protection Bypass for Automation，仅交给该项目的 Inngest 集成，用于访问受保护的预览部署；该凭据不能限定到单分支或路由，不替代 Inngest 签名或应用鉴权。不得改变本地及生产业务环境、数据或调度。

## 界面与视觉规范

### 选定方向

采用**暗夜信号控制台（深色体系）**作为全站视觉基座，结合**首页 Bento 指挥中心**与**电影库策展海报墙**布局。所有概念预览图仅存放在项目根目录 `.local/`（由 `.gitignore` 忽略），不随 OpenSpec 或 Git 提交。

### 设计 Token 与交互基线

- **色彩与层次**：画布底色 `#090E1A`、左侧导航栏 `#0C1222`、卡片表面 `#11192C`、细边框 `1px solid #1E2B48`、卡片圆角 `12px–14px`。主文字 `#F1F5F9`、次文字 `#94A3B8`，正文与状态文本保持 WCAG AA（≥ 4.5:1）对比度。
- **语义色**：电光靛蓝 `#687BFF`（焦点与高亮）；主操作和分段选中态使用 `#5163F2` 至 `#5466F5` 的填充配白字（全程 ≥ 4.5:1）。荧光薄荷绿 `#35EDB4` 用于运行中信号、健康、新鲜缓存、导航激活与启用开关，不使用大面积纯色块；琥珀黄 `#FBBF24`（429 共享退避、译文回退、已过期缓存）、珊瑚红 `#F87171`（失败项与撤销密钥）。
- **字体与数字**：所有 TMDB ID、时间戳、并发配额、缓存天数和流水线计数使用等宽对齐数字（tabular numerals），避免轮询刷新抖动。
- **后台导航**：受保护的管理页面统一固定左侧 `220px` 深色导航栏（顶部 CineRelay C-Relay 标识 + 8 项线性 SVG 图标与中文标签：总览、任务配置、运行历史、电影库、TMDB 凭据池、外部应用、操作审计、API 文档；底部显示受邀管理员身份和退出入口；当前页以左侧薄荷绿竖条与微弱青绿底高亮）。窄屏下折叠为抽屉菜单。
- **可访问性与交互约束**：统一使用线性 SVG 图标（Lucide），禁用 Emoji 图标；关键状态同时用色彩与图标／文字表达；保留清晰键盘焦点环，区分只读态与禁用态，尊重 `prefers-reduced-motion`；每页最多一个实心靛蓝主 CTA；同页其他操作用描边或浅底描边区分。1.1 的静态演示使用轻量标签标记，未接入的管理动作显示局部反馈，不提交写入或调度。危险操作（如撤销外部密钥）使用红色描边并在空间上与主操作分离。

- **运营总览（首页 · Bento 指挥中心）**：顶部栏包含页面标题、TMDB 共享预算状态点、`⌘K` 快捷检索、次要「试抓 5 部」与主「新建任务」按钮；主体采用非对称 Bento 栅格，依次呈现实时同步流水线（完成率 + 四阶段 Relay 节点流）、快速试抓卡片（筛选条件 + 立即试抓 5 部）、TMDB 凭据池与分段共享预算、VidAll 外部 API 缓存命中趋势与 `/docs/api` 入口、底部 6 卡 `zh-CN` 最近入库电影海报条。

- **任务模板列表（`/jobs`）**：三卡概览、搜索和模式分段筛选，展示模板选片条件、计划、启用态、游标和最近运行。提供试抓、立即运行与编辑入口；范围变化提示回填或重建游标。新建与编辑进入 `/jobs/new`、`/jobs/[id]`，兼容 `/jobs?sample=1`。
- **任务配置与试抓 5 部**：左右分栏（左 55% 表单配置，右 45% 试抓样本诊断）。表单按「01 选片与内容」与「02 运行安排」分组，全部使用可见标签与下拉／分段控件，无需手写 JSON 或 Cron；右侧提示「最多 5 部 · 不写库 · 不推进游标」；2.2 在运行详情页展示抽样／成功／入库（恒为 0）／失败统计及逐条诊断，不断言上游实际使用的译文语言。正式运行入口在已保存的一次性回填模板上。
- **运行历史（`/runs`）**：状态分段、搜索、触发方式筛选、分页；置顶运行聚焦条展示 Relay 进度和 429 共享退避。四阶段计数表覆盖运行中、试抓未写库、部分失败、派发失败可重派和完成。行入口进入 `/runs/[id]`，未知 ID 返回 404。
- **正式运行详情与安全重试**：顶部展示计划时间、实际开始时间与已锁定配置快照；2.3 在「正式同步进度」卡显示发现／入队、已抓取、已入库与失败计数，按电影列出抓取与入库状态；存在失败则显示原因和允许重试的时间，支持重试未完成项。共享 429 冷却留到 3.2。
- **凭据与访问控制（TMDB 池与外部应用）**：上卡展示 429 共享退避横幅、细渐变共享并发进度条及脱敏 TMDB 凭据启停列表；下卡展示仅服务端调用的 VidAll 外部应用凭据表（含完整「操作」列与独立红色「撤销」按钮）及 `/docs/api` 文档入口。
- **登录（`/login`）**：无侧栏的居中深色卡片与柔和径向光；说明白名单、外部密钥隔离与只读审计，单一 GitHub OAuth 主 CTA，不展示受保护文档入口。
- **外部应用（`/consumers`）**：不对称 Bento 展示 24 小时调用量、缓存命中率趋势、陈旧期兜底和脱敏 Bearer 示例；凭据表提供珊瑚红描边撤销，并说明仅存哈希和明文单次展示。
- **操作审计（`/audit`）**：无实心主 CTA 的只读视图，多条件筛选与分页；表格包含时间、操作者、类别、动作与目标及结果，不展示原始请求或密钥。

- 1.1 的五页用合成数据完成视觉验收；登录、审计与电影库已接入真实后端，未实现的业务页面仍只展示合成数据，凭据、任务及调度演示动作不触发后端。窄屏可在表格容器内横向滚动，不产生整页横向溢出。

## Risks / Trade-offs

- Inngest 只能立即接收手动触发事件，不能承诺无等待开始；界面显示明确排队和退避状态。
- 高频调度及轮询可能消耗 Neon 计算额度；改频率前用实际用量验证。需要更高频率或新增第三方费用时另行决策。
- 多凭据不等于多份速率额度；源数据缺失不推断为下架或旧 ID 合并。
